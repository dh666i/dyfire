# Dyfire 0.4.6

本版重整构建、镜像分发和站内更新流程，减少重复构建与不必要的浏览器运行层下载，并让管理员能够看清下载进展和各服务的实际版本。

- 四个业务容器保持原职责，改用两类镜像：网页与监控使用不包含 Chromium 的 Web 镜像；登录与发送共用浏览器镜像。仅更新网页时，登录、发送和监控服务继续使用原版本运行。
- 运行环境与应用代码分别维护。日常应用构建直接使用已经验证、固定摘要的运行环境；每周维护及手动维护产出新的运行环境候选，通过检查后更新锁定文件。依赖或浏览器变化时仍需要重新验证运行环境，不永久冻结安全补丁。
- 主分支为每个组件构建一次候选镜像，完整质量门禁、容器验收和安全扫描通过后，发行阶段直接提升同一提交的已验证摘要，不再重复构建。测试分为四个隔离分片，并核对收集清单，避免为提速漏掉测试。
- 构建缓存分别保存在镜像仓库中。运行层、字体和未变化的应用层可复用；正式发行保留 SBOM 与构建来源证明，服务器只拉取对应的 Linux amd64 运行镜像。
- 更新请求持久化记录接受、下载、切换和验收阶段。更新器意外重启后继续核对原操作；已成功切换的版本通过检查后提交，未完成的切换恢复原版本。下载连接中断可重试，已经完成的镜像层保留；恢复过程不覆盖业务数据库。
- 兼容的网页更新先启动临时候选并检查健康与版本，再切换流量、替换标准 Web 容器，验收通过后切回。旧请求先排空，长连接未结束时保留承载它的实例，随后在空闲时清理；失败则恢复原网页版本。只有 Dyfire 源站上游参与切换。
- 管理员页面分别显示网页、登录与发送、最新版本，区分仅更新网页和完整更新的预计新增下载量，显示下载量、复用量、速度、重试与长时间无进展。未知进度不显示虚假的百分比，更新阶段使用中文；请求接受后锁定按钮，避免重复提交。网页已更新但执行服务仍旧时，完整更新入口继续可用。

首次从旧的共享大镜像迁移，需要下载两类新运行环境的缺失基础层，这次下载仍可能较大。后续同一运行环境上的应用更新按镜像层复用，不需要每次重新下载 Chromium；浏览器升级、系统补丁更新或本机缓存被清理时，仍可能出现较大的下载。界面显示的是根据当前运行镜像估算的下载上限，实际本机缓存命中时可以更小。

首次迁移必须先同步宿主更新器与组件镜像配置，再使用新发行清单；旧更新器会拒绝新的清单格式，避免误将 Web 镜像用于登录和发送。兼容性或数据库结构不匹配的版本不允许单独更新网页，需使用完整更新。完整更新及回滚仍会重启相关服务，不能与网页流量切换等同。

本版暂不接入新的国内镜像仓库。服务器继续从 GHCR 拉取固定摘要镜像，跨境网络仍会影响首次或大层下载速度；本版通过复用镜像层、分离运行环境和取消发行阶段重建减少工作量。构建耗时及线上下载提速幅度以实际流水线和部署记录为准，不承诺未取得实测证据的秒数或倍数。

本版保留现有站内界面与任务规则，不增加管理员验证步骤，也不修改香港桥接或其他站点。Web 切换安装、兼容性和恢复细节见 [Web 更新切换](web-handoff.md)。
