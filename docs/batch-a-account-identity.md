**第一批：账号身份、免费恢复与交互正确性**

目标版本：0.3.42。对应综合复核报告 R01/R02/R03/R10。当前文档说明代码与迁移约束，不能作为“已经部署”的证明。

- 账号接口的真实成功返回可能没有 `error_code`。现在用成功响应、稳定 user_id/user_id_str、一致性与访客状态共同确认身份，不依赖创作者中心 XPath。
- 新扫码必须取得稳定身份；全局唯一索引保护并发重复绑定。可改的公开抖音号仅展示。
- 重新验证原账号前，缺身份的旧记录只能使用原凭据补身份；不能拿新扫码结果来证明原账号是谁。身份不匹配或无法确认时保留原凭据与任务。
- 实际发送先核对当前平台身份，再选择好友、进入提交步骤。尚未补身份的旧账号可以在这个安全检查点渐进登记；发现冲突时不发送。
- 免费首任务的恢复与主执行使用同一任务资格规则；未来生效订阅、超额、主动暂停、已提交任务仍不能通过此路径发送。
- 下拉框独立为组件支持模块，修复点选空引用、回车多移一项、内部滚动关闭；方向键不提交，回车确认当前高亮，跳过禁用项。
- 首次执行引导以真实成功历史为准，不能用“任务已创建”替代；包括今天列表之外的成功历史。

**存量迁移**

SQLite schema 19 → 20 只添加可空的稳定身份列和唯一索引，不改旧凭据、任务、账号主键或日程；PostgreSQL 同样采用增量列/索引。发行兼容协议 schema 仍为1，二者用途不同。

先在隔离数据副本验证 schema 与账号/任务保持，再在部署后的受控环境核对原身份。命令默认只检查；输出账号记录ID及结果，不输出稳定UID、Cookie或抖音资料。

```sh
python -m spark_console.cli account-identities --active-only
python -m spark_console.cli account-identities --active-only --apply
python -m spark_console.cli account-identities
```

`--apply`仅保存从原登录态验证出的身份元数据，带凭据版本CAS保护。忙碌、不可解密、接口不可用、身份重复或凭据已更新会单独报告，不猜测、不合并账号。

`ready_for_new_bindings`表示当前有启用任务的旧账号已完成身份保护；`pending_accounts`仍显示全部待核对旧记录数量。无任务/已暂停的旧记录保留，不因其原态不可读冻结整站新增；它们以后真正发送前仍必须通过身份核对。

2026-11-06 的生产只读预检：2个在用账号能读取身份且互不重复；另外2个无任务或已暂停的旧账号无法从原态读取身份。本次预检未写数据库、未发送消息。后两者需要本人恢复有效原登录态，或走清楚确认的解绑/重新绑定流程；不能静默把另一个抖音号替换到原任务上。

**验证范围**

新增回归覆盖：真实响应结构、异常/冲突/访客身份、敏感字段不回显、数据库唯一索引、身份CAS、迁移与dry-run、存量冲突、真实发送前拒绝身份不明、免费/过期首任务恢复、下拉鼠标和键盘，以及历史首次成功。

Windows现有备份目录fsync测试不兼容 `os.open(directory)`；本批未修改备份逻辑，Linux CI应完整运行该用例。真实抖音扫码/手机键盘与逐页视觉仍需另行验收，单元测试不能替代。
