**Dyfire 前端视觉与交互调研 · 2026-11-10**

建议保留当前暖橙品牌色、圆角、玻璃导航和统一 React 架构，重点改善信息层级、字号、手机布局和操作反馈。现有界面已经有识别度；最明显的提升空间在于日常操作时的清晰、紧凑、一致，以及动画与真实业务状态的对应。

本文件保留调研时的发现与建议。用户确认后已推进本地实现，**当前完成情况以 [UI 体验改进完成清单](ui-experience-implementation-2026-11-10.md) 为准**；下文“未实施”等状态记录的是调研当时的状态。本轮尚未发布或部署。

**反馈的统一规则**

- 成功：操作附近短反馈，必要时 Toast 补充；同一次操作不在三个地方重复弹出。
- 可纠正输入错误：紧贴字段，保留输入；不能只显示顶部一句通用“请求未完成”。
- 持续阻塞：账号需验证、网络未恢复等保留可操作提示；不与普通成功提示一起在几秒后消失。
- 结果待核实：明确“请求是否完成暂时无法确认”，提供查看记录/只读核对。沿用现有防重发策略。
- 禁用：在需要时说明为什么不能创建/兑换，不只把按钮变淡。
- Toast：可点击关闭、键盘关闭，指针悬停或键盘聚焦时暂停消失倒计时，避免用户没读完或点不到。
- 全部已完成/暂无任务/筛选无结果/加载失败分别设计，不使用同一种空白卡片。
- 可撤销只用于后端明确支持的可逆修改；不把删除、解绑和实际发送做成没有保障的假撤销。

**技术实施建议**

继续使用当前 React + Vite。现有技术足够实现建议视觉，不需要为此迁移 Next.js，也不需要引入 WebGL。

样式仍按 `react.css → react-polish.css → react-fire.css` 覆盖，手机布局同时存在按子元素位置和按语义类名指定区域的规则。手机用户列宽问题说明这些规则已经会互相影响。建议按视觉变量、基础组件、业务组件逐步归并，删除对应的重复声明，而不是继续在文件末尾追加覆盖。

弹窗、菜单、选择器、提示可逐步采用一个无样式组件基础，例如 Base UI，并套用现在的皮肤。它的价值是焦点、键盘、弹层行为；不是把整站换成库自带外观。应逐个替换并验收，不同时引入两三套基础组件库。

保留 Motion 与现有轻量 CSS/WAAPI 动画，为各场景统一时长和取消机制。优先用 transform/opacity；大面积模糊、持续辉光、频繁高度动画要实测。减少动画模式必须在真实交互下验证，不能只让测试关闭动画后通过。

本地预览应补齐静态资源并复用经过契约检查的样例数据。当前演示数据的日期、关联字段和接口覆盖不完整，可能造成预览与上线感受不同；这不等同于生产接口故障。
