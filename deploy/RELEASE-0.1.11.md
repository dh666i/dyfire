# 0.1.11 全站视觉与操作一致性

保留 Studio 首页构图、标志及业务接口，统一普通用户和管理员的基础视觉与操作规则。

## 本次改动
- 共享 design_system.css / design_system.js：独立深浅色配色、低饱和强调色、语义状态、8px 卡片、银灰追光、字体与数字层级、焦点和移动端尺度。
- 卡片装饰单独裁切，不裁切菜单与焦点；触屏和减少动态效果设置关闭追光；没有持续动画循环。
- 头像菜单和行菜单统一材质、尺寸、键盘行为、互斥及视口定位，支持浏览器顶层弹出，避免父卡片裁切。
- 两个任务入口采用创建侧面板；手机全屏，关闭前提示且本页保留草稿，创建确认在同一面板内显示。
- Studio 任务按账号分组、异常账号优先、分页、折叠记忆、账号筛选、新任务定位；服务端任务分组增加计数和折叠。
- 任务和执行记录使用紧凑桌面排版与独立移动布局；移动记录保留所属账号，所有筛选均可清除。
- 好友多选增加仅看已选；重复读取不累加内部好友数组；同账号刷新保留旧列表与选择，错误不清空草稿。
- Studio 提交前后比较账号、时间、消息和好友选择，防止确认期间变化；成功反馈实际创建数量。
- 账号备注编辑默认收起，删除置于更多菜单，保持确认及 CSRF 保护。
- 快捷概览、账号、记录入口归并到功能完整的正式页面，消除重复简化实现。
- 兑换成功直接展示新额度与到期时间；后台诊断明确区分自动备份计划与历史结果，不启用备份。
- 资源使用版本参数或 Vite 内容哈希，避免旧脚本与新布局混用。

## 已有能力复核保留
概览异常优先、好友头像、同步会话范围、原生续火花默认、任务创建归属/额度校验、批量部分失败反馈、账号验证与复核、发送证据分类、管理员权限、订阅到期说明、服务器资源监控、密码可见按钮、用户关联管理、邮件设置、更新锁和回滚。
没有改写抖音登录、验证输入、调度或发送协议，没有重新启用自动备份。

## 验收与边界
- 后端页面矩阵：普通用户 9 个页面、管理员 10 个页面；权限拒绝；旧成功备份和已停用计划并存。
- jsdom 交互检查：单卡片装饰、输入节点稳定、菜单互斥、草稿保留、面板内确认、55 个任务分页分组、新任务定位、仅看已选、重复点击保护。
- 前端生产构建与 GitHub Docker 完整构建；按用户要求不使用浏览器控制。
- 深/浅色和 320/390/768/1024/1440px 布局在 CSS 中分别处理，但真实视觉、屏幕阅读器及手机键盘仍需人工验收；jsdom 不负责布局渲染，不能代替这些检查。
- 不承诺抖音登录永久有效，未确认发送不自动重发；未增加任何新发信服务。
- 0.1.10 已记录的旧部署脚本测试及旧主题断言遗留问题不作为本次功能完成依据。
